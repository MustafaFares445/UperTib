## 1. Join rule

The stable joins are requirement references in Phase 1/4 artifacts and canonical IDs. A requirement does not need to be repeated in every intermediate prose block to remain traceable: Phase 1 owns the screen and flow, Phase 2 owns the same screen's WF, Phase 4 owns its WGT composition, and Phase 5 gives every allocated WGT exactly one implementation contract.

Forward chain:

`FR -> JTBD/FLOW where directly cited -> SCR -> WF -> WGT composition -> WGT implementation contract`.

Reverse chain:

`implementation contract -> WGT -> SCR placements -> WF/SCR/FLOW -> canonical FR`.

All 60 FR have at least one documented Phase 1 screen. 46 FR are cited directly by at least one WGT specification; 14 FR reach implementation through the WGT composition of their documented screens rather than by repeating the FR on a widget heading.
